# 状态、审核与恢复

## 状态循环

核对当前需求和成果 → 选择下一项已授权且依赖就绪的工作 → 调用真实工具或交付文本 → 检查结果 → 保存状态 → 继续。进度说明不能代替行动。需要真实用户决定、缺少必要能力/资源、明确暂停或完成所需交付时停止；普通后台任务运行中不等于制作结束。

状态可以是前期草稿、等待审核、资产准备、声音准备、分镜准备、镜头执行、镜头检查、后期、等待终审、导出中、已交付或局部阻塞。名称是项目记录约定，不是 API 枚举。用户只要前期草案时，完整交付草案就是该范围完成，不强制经过后续状态。

## 版本与决定

每项成果具有稳定逻辑 ID、版本、内容摘要/哈希（能计算时）、真实位置、检查结论及当前批准。审核必须指向已展示的内容；用户可以在卡片、表单或普通聊天批准明确版本。若内容跨页，先给清晰顺序并保证完整可读；不要要求批准未见图片或空音频。

默认在视觉方向、剧本、视觉资产、声音候选、可执行分镜和最终预览处合并审核。按任务复杂度合并小阶段，按用户已有明确批准或批量授权推进；不把默认流程变成重复审批。用户可只要草案或预先授权部分创作选择，记录其范围，不越过其费用、外部发布或宿主权限限制。

保留以下区别：

- 需求确认不等于为所有付费工具授予无限费用。
- 分镜方案批准可以授权约定范围的批量制作；不是批准任何后续创意改写。
- 技术修复如重编码、修复路径和无内容变化的裁切不必增加创作审核。
- 换脸、换声音、改台词、关键动作或结尾属于内容变更，只重开受影响批准。
- 最终预览批准绑定当前音画、字幕和时间线版本；变化后不能复用旧终审。
- 不回答、超时、推荐项被选中但未提交、工具成功都不等于同意。

## 依赖与失效

保存“剧本行 → 角色/道具/场景 → 镜头板/音频 → 生成单元 → 准备镜头 → 剪辑片段 → 导出”的依赖。某角色改服装仅失效含该服装的板和镜头；改配乐仅影响混音、预览与导出。显示文字翻译、成果搬移或无内容变化的编码转换不自动使整片失效。

同场景续接可使用已通过技术检查的前驱，不额外要求逐镜用户批准，除非项目约定了逐镜审核。只并发执行互不依赖且工具允许并发的任务；共享时间线/画布写入串行处理，防止互相覆盖。

## 接受状态与重复提交

每次请求记录请求指纹、目标资产版本、任务 ID、提交时间、是否接受及输出。超时、空列表或 ID 未回传不能证明服务端未接受。先查询已有任务、已保存节点和返回结果；接受未知时不重复付费提交。

已接受的正常任务用真实状态轮询，不重提。确认未接受且参数修复后，才提交新请求。没有查询能力且接受未知时保留局部阻塞，继续其他独立工作，不通过重复生成探测。

## 有界修复

- 参数错误：依据实际错误修正一次，重新校验；仍失败时最多再做一次不同且有证据的修正。不能原样反复执行。
- 429/暂时5xx：尊重 Retry-After；仅在上次确定未接受/确定终止的前提下最多两次补交，宿主更严限制优先。
- 画布或文件同步：最多三次不产生媒体的读取/对账，修复已有成果；不能用读取预算增加生成次数。
- 审核组件提交失败：单独恢复决定，不重做已生成媒体。
- 内容/版权策略拒绝：保存请求及具体错误，不换接口、遮标、改名或静音来让同一被拒内容绕过。提供真正原创修改、获准替代或服务商复核；只改受影响部分。
- 共享输入路径出错：暂停未提交的同类队列，修复实际输入后恢复，避免批量重复报错。

## 恢复与交接

保存已完成成果、待定决定、接受但未完任务、失败原因、尝试次数、下一步和真实位置。新会话先核对这些内容，不从头重问。无持久化能力时给一段可复制交接记录并说明只能由用户带到下一会话。

完成报告分开列明“已生成”“已检查”“未检查”“阻塞”和“仅计划”。不能用任务成功提示、编辑器截图或尚未结束的渲染承诺替代实际交付。
